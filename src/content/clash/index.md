## 第一模块：Clash 生态演进史与 2026 后 Clash 时代全景格局

理解当下的客户端生态，首先必须理清 Clash 在过去几年中经历的技术震荡与社区涅槃。

### 1. 原版 Clash 与 Clash for Windows (CFW) 停更始末
在 2023 年 11 月之前，由开发者 `Dreamacro` 主导的开源核心 **Clash** 以及由开发者 `Fndroid` 开发的 **Clash for Windows (CFW)** 是中文出海网络事实上的绝对统治者。几乎所有机场的教程、配套分发包均以 CFW 为基准制作。

然而，2023 年底发生了一系列引发行业震动的不可抗力事件：
- 原版 Clash 核心开源仓库被作者主动删除（`Repository deleted`）；
- 紧接着，Clash for Windows 以及多个主流衍生项目宣布停止维护并清空代码库。

原版停更留下了严重的生态隐患：
1. **旧内核无法支持新协议**：原版 Clash 核心永久停留在对 Shadowsocks、VMess 等传统协议的支持阶段，完全无法原生解析 2024–2026 年成为抗封锁主力的 **VLESS (Reality)**、**Hysteria 2** 以及 **TUIC v5** 等现代化基于 UDP/TLS 拟态的抗封锁协议。
2. **高危安全漏洞无人修补**：CFW 基于庞大且陈旧的 Electron 框架打包，其内置的 Chromium 与 Node.js 运行时包含多个已知且公开的远程代码执行（RCE）高危安全漏洞。继续使用旧版 CFW，相当于在本地网络中敞开了一道随时可被黑客利用的后门。

### 2. 开源火炬的接力：Mihomo 内核与跨平台现代客户端矩阵
在原版停更后，全球开源社区迅速重组。其中，**Clash.Meta（现正式更名为 Mihomo）** 核心团队接过了代码维护的重任，并进行了翻天覆地的现代化重构：
- **全面重构协议栈**：原生支持全套现代协议，重构了 DNS 解析引擎，引入了基于路由元数据的 Sniff（域名嗅探）引擎与 Rule-Providers 动态规则集。
- **图形客户端百花齐放**：在前端 GUI 层面，社区彻底抛弃了臃肿陈旧的旧架构，诞生了以 **Clash Verge Rev** 为代表的基于 Rust/Tauri 技术的超轻量客户端，以及适配移动端的 **Clash Meta for Android** 与 **Flclash**，共同构成了 2026 年稳固健康的现代 Clash 生态矩阵。

### 1. 为什么 Clash Verge Rev 能全面碾压旧版 CFW？
- **极低的内存占用与轻量化启动**：旧版 CFW 由于 Electron 框架的臃肿，开机启动常驻内存往往高达 200MB–450MB，且冷启动耗时 3–5 秒；而 Clash Verge Rev 采用 Rust + 操作系统原生 Webview（WebView2 / WebKit）渲染，开机常驻内存仅为 **30MB - 60MB**，冷启动几乎在 0.5 秒内瞬间完成。
- **内置 Mihomo 旗舰核心**：开箱即用，无需用户手动寻找第三方内核替换，天然完美支持机场下发的所有前沿抗封锁加密协议。
- **原生的“服务模式（Service Mode）”与 TUN 网卡支持**：在 Windows 系统中，普通软件创建虚拟网卡需要管理员权限。Verge Rev 内置了轻量级的系统级 Background Service，安装服务后，用户只需在界面上轻轻一拨开关，即可在毫无系统弹窗干扰的情况下，秒速启用全局 TUN 虚拟网卡，彻底接管包括游戏、终端、虚拟机在内的全量网络流量。
- **强大的“配置扩展（Merge & Script）”生态**：支持在不破坏机场原始订阅的前提下，通过图形化界面插入自定义的 Proxy-Group（代理组）、自定义规则集（Rules）甚至是 JavaScript 脚本动态重构配置，灵活性与可维护性冠绝全场。

## 六、Clash 核心配置结构解密与自定义分流扩展语法实战

深入掌握 Clash 的高级玩法，必须理解 YAML 配置文件的核心层级，并学会使用 Verge Rev 的“配置合并（Merge）”机制自定义专属分流规则。

### 1. Clash YAML 配置文件的四大核心骨架
一份标准的 Clash 配置文件由以下四个顶层关键字严格组织而成：
- **`port` / `socks-port` / `mixed-port`（网络监听端口）**：
  定义 Clash 在本地电脑上开启的代理端口。现代配置中强烈推荐统一使用 `mixed-port: 7897`（混合端口），它可以同时接受 HTTP 网页代理与 SOCKS5 传输层代理，大幅简化客户端配置。
- **`proxies`（底层节点物理定义）**：
  保存所有节点的连接参数（服务器地址、端口、协议类型、UUID 密钥、加密套件、传输层伪装 TLS SNI 等）。这是机场订阅下发的最核心硬件资产。
- **`proxy-groups`（逻辑策略组）**：
  将上述底层节点按照地区（香港/日本/美国）、用途（ChatGPT专线/流媒体/电报）、算法（自动优选 URL-Test / 故障转移 Fallback / 手动选择 Select）进行重新打包编组。
- **`rules`（路由分流规则列表）**：
  自上而下的分流匹配列表。当本地发出一笔网络请求时，内核会按照规则列表从第一行开始逐条向下比对，**一旦命中任意一条规则，立即终止后续比对，直接执行对应策略**。

### 2. 避免直接修改配置：使用 Merge（合并）与 Script 扩展
许多新手常犯的一个严重错误是：直接用记事本打开下载好的机场配置文件去修改规则。结果每次点击“更新订阅”，机场下发的新文件会瞬间将用户的全部本地修改彻底覆盖清空！

**在 Clash Verge Rev 中，正确的解决方案是使用“订阅扩展（Merge）”**：
1. 点击左侧导航栏的 “**订阅扩展（Script / Merge）**”；
2. 新建一个类型为 `Merge` 的规则集，命名为 `My-Custom-Rules`；
3. 在编辑框中编写你的专属插入规则，例如将 OpenAI 强制绑定至干净的美国原生节点策略组，并将公司私有内部域名设为强制直连：

```yaml
# 自动插入到机场配置最顶部的自定义分流策略
prepend-rules:
  # 1. 办公私有内部域名与局域网段强制直连 (DIRECT)
  - DOMAIN-SUFFIX,mycompany.local,DIRECT
  - DOMAIN-KEYWORD,corp-intranet,DIRECT
  - IP-CIDR,192.168.0.0/16,DIRECT,no-resolve
  - IP-CIDR,10.0.0.0/8,DIRECT,no-resolve

  # 2. 海外大模型核心资产路由至专属低风控美国原生节点组
  - DOMAIN-SUFFIX,openai.com,🤖 OpenAI专选
  - DOMAIN-SUFFIX,chatgpt.com,🤖 OpenAI专选
  - DOMAIN-SUFFIX,claude.ai,🤖 OpenAI专选
  - DOMAIN-SUFFIX,anthropic.com,🤖 OpenAI专选

  # 3. 常见漏网大陆国内应用与流媒体直连加速
  - DOMAIN-SUFFIX,bilibili.com,DIRECT
  - DOMAIN-SUFFIX,163.com,DIRECT
  - DOMAIN-SUFFIX,qq.com,DIRECT
  - GEOIP,CN,DIRECT
```

点击保存并在“配置”管理页中关联该扩展。从此以后，无论机场如何高频更新节点，你的自定义规则永远稳定驻留在规则表的最顶端，实现了高度解耦与永久生效！

## 七、Mihomo (Clash.Meta) 核心协议与高级分流全景剖析

Mihomo 核心之所以能成为 2026 年的标准基石，在于其对底层网络协议与 DNS 体系的革新支持。

### 1. VLESS Reality 与 Hysteria 2 抗封锁协议深度解密
- **VLESS Reality（拟态隐形标杆）**：
  传统 TLS 加密虽然内容保密，但由于需要自建或申请域名证书，审查探针可以通过 SNI 探测与证书链比对识别出未备案的小型翻墙网站。而 VLESS Reality 创造性地实现了“借鸡生蛋”：它借用真实境外科技大厂（如苹果、微软、亚马逊）的合法公网 TLS 证书指纹与 443 端口，使得所有代理流量在物理审查设备眼中完全等同于一次对 Apple 官网的标准安全访问，具备无与伦比的抗封锁生存能力。
- **Hysteria 2（基于 UDP 的弱网暴力加速）**：
  专为恶劣高丢包网络环境研发。传统基于 TCP 的协议一旦在跨洋公网中发生 2% 丢包，TCP 的拥塞控制机制便会强制降速。而 Hysteria 2 基于改进的 QUIC (UDP) 协议，内置了自主研发的拥塞控制算法，即使在晚高峰丢包高达 15% 的公网线路上，依然能强行驱动出满带宽的 4K 视频流。

### 2. Fake-IP 模式与 DNS 污染根治方案
在 Verge Rev 的内核设置中，**Fake-IP 模式是根绝本地运营商 DNS 投毒的最佳方案**：

```
                    【Fake-IP 模式工作拓扑与速度提升原理】
  本地应用程序 ──────► 发起域名解析请求 (如访问 `youtube.com`)
                             │
                             ▼
  Clash 本地内核 ─────► 【零等待秒级返回虚构保留 IP】 (如 `198.18.0.1`)
                             │
  应用程序建立连接 ──► 向 `198.18.0.1` 发送 HTTP 请求
                             │
                             ▼
  Clash 内核拦截 ─────► 将虚构 IP 还原为原始域名 `youtube.com`
                             │
                             ▼
  加密数据管道 ───────► 直达海外远端专线代理服务器，由远端执行真实解析
  [彻底杜绝本地宽带运营商的明文 DNS 投毒，网页首包延迟降低 50ms - 150ms]
```

### 3. TUN 模式核心堆栈（gVisor vs System vs Mixed）对比大表

开启 TUN 虚拟网卡时，用户可以在 Verge Rev 设置中选择不同的网络协议栈（Stack）。不同的堆栈对系统资源的消耗与网络稳定性差异显著：

| TUN 协议栈模式 | 底层技术实现架构 | 吞吐量与极限速率 | 典型 CPU 资源占用 | 驱动稳定性与兼容性 | 最佳适用场景 |
| :--- | :--- | :---: | :---: | :---: | :--- |
| **gVisor (推荐首选)** | 谷歌开源的纯 Go 用户空间网络协议栈实现 | 极高 (跑满 800Mbps+) | 轻微偏高 (多 2%-5%) | 🌟🌟🌟🌟🌟<br>**绝对稳定，永不蓝屏** | 绝大多数 Windows 10/11 与 macOS 用户的日常首选 |

## 八、Clash 自动化测速机制、策略组算法与容差调优深度指南

在日常使用中，许多用户在“代理（Proxies）”界面中看到“自动选择（URL-Test）”、“故障转移（Fallback）”策略组，却不知道其底层的测速探针是如何运转的，常常因为默认配置不合理导致后台流量被测速大包频繁消耗，或者节点在毫秒级波动下频繁切换造成正在进行的在线会议和游戏断线重连。

### 1. URL-Test 测速探测端点与参数底层剖析
Clash 内核对节点的健康检查与延迟度量，依靠的是向特定的“204 探测服务器”周期性发送轻量级的 HTTP GET 请求：
- **默认探测端点选择**：原版配置常用 `http://www.gstatic.com/generate_204`。但由于 Google 的该服务在国内网络环境下本身处于被屏蔽状态，在未建立连接前可能出现探测失败。现代配置更推荐使用 Cloudflare 或高可用的国际 CDN 端点：
  - `http://cp.cloudflare.com/generate_204`（全球低延迟，响应极快）
  - `https://www.qualcomm.cn/generate_204`（国内友好，判定直连网络）
- **三大核心调优参数（规避频繁跳节点的关键）**：
  - **`interval: 300`（测试时间间隔，单位：秒）**：默认 300 秒（5分钟）测试一次。对于流量紧张的用户，建议调整为 `600` 或 `1200` 秒，避免过于高频的后台测速消耗节点流量。
  - **`tolerance: 50`（切换容差，单位：毫秒）**：这是**防止网络闪断的最核心参数**！如果容差设置为 0，当 A 节点延迟为 20ms、B 节点延迟为 21ms 时，微小的网络抖动就会导致内核在 A 和 B 之间疯狂切换，直接击穿正在保持的长连接（如 Zoom 会议或 Telegram 语音）。将 `tolerance` 设置为 `50ms` 后，只有当备选节点的延迟比当前节点**低 50ms 以上**时，内核才会触发切换，保障了长连接的坚挺稳定。
  - **`lazy: true`（惰性测试模式）**：当开启 `lazy: true` 时，如果当前策略组没有任何用户流量正在流动，内核会自动挂起定时测速，直到用户下一次打开海外网页时才唤醒测试，杜绝了电脑静置待机时浪费流量。

### 2. 策略组四大主流类型的适用场景与行为逻辑
- **`select`（手动选择）**：完全由用户在界面上手动点击指定节点。适合特定对公网 IP 纯净度与固定位置要求极高的业务（如维护核心商业账号、ChatGPT 固定使用美国原生节点）。
- **`url-test`（自动优选最低延迟）**：全自动根据探针返回的毫秒数路由。适合日常浏览网页、观看 YouTube 视频流。
- **`fallback`（故障转移 / 热备可用性保活）**：按照节点列表从上到下的顺序优先使用第一个节点。只有当第一个节点彻底宕机断连时，才自动无缝切换到第二个备用节点；一旦第一个节点恢复，立即切回。这是**防失联容灾架构的标准配置**！
- **`load-balance`（负载均衡）**：通过源 IP 哈希或循环轮询将连接分发到不同节点。仅建议在多线程批量抓取、自动化爬虫数据采集等特定极客场景使用。

## 十、保姆级新手实战教程：模式切换、系统代理与 TUN 全局接管

### 1. 三大分流模式的精准切换守则
在界面的“代理（Proxies）”页面顶部，提供三种路由模式切换按钮：
- **规则（Rule）模式 —— 99% 场景下的日常唯一推荐**：
  根据配置文件中内置的 GeoIP 中国大陆 IP 数据库与 Geosite 域名列表自动执行分流。
  - 访问百度、淘宝、微信、B站、知乎：自动走本地宽带直连（Direct），不消耗机场流量，国内秒开；
  - 访问 Google、YouTube、GitHub、ChatGPT：自动匹配规则经由你选择的专线节点加密转发。
- **全局（Global）模式 —— 仅用于排查特定冷门软件**：
  强制所有网络请求（无论国内还是国外）全部走选中的海外节点。容易导致国内软件报错、网银风控，非测试需求切勿常驻开启。
- **直连（Direct）模式 —— 应急停用**：
  所有流量直接走本地网络，等同于完全不翻墙。

### 2. 开启系统代理与进阶 TUN 模式
- **常规网页冲浪（系统代理）**：
  直接在主界面将 “**系统代理（System Proxy）**” 开关拨至开启状态。此时浏览器即可畅通访问海外网站。
- **全量接管全平台流量（TUN 模式）**：
  如果你遇到“浏览器能翻墙，但运行的 Steam 游戏外服掉线、Discord 客户端连不上、CMD 命令行里的 `curl` 或 `git clone` 无法加速”的问题，说明这些软件不会自动遵循 Windows 的 HTTP 代理环境变量。
  - **解决对策**：在 Verge Rev 设置中找到“服务模式（Service Mode）”，点击安装；安装完成后，直接打开 “**TUN 模式**” 开关。系统会在网卡列表中生成一张虚拟网卡，从底层全量拦截电脑中所有进程发出的所有网络流量，实现 100% 真正的全局透明加速！

## 十一、Clash 终极高频故障排查与应急自救手册

在日常使用中，遇到突发断网或连接异常时，切勿盲目重装软件。请严格按照以下六大实战场景进行自愈自救：

### 1. 故障 A：节点全部超时全红（Timeout / -1ms）
这是所有用户遭遇率最高的终极故障，请按以下 4 步排查清单自愈：
1. **排查系统时钟偏差**：按 `Win + R` 键输入 `timedate.cpl` 打开日期和时间设置，检查当前系统时间是否与北京时间秒级对齐。时差超过 60 秒立即点击“Internet 时间”进行“立即同步”。
2. **排查杀软与网络防火墙**：检查火绒、360 或 Windows Defender 防火墙是否拦截了 `clash-verge.exe` 或 `mihomo.exe` 的入站和出站规则。
3. **排查机场账户状态**：用浏览器登录机场后台，确认本周期流量额度是否耗尽、或者服务是否到期。
4. **更换本地网络环境验证**：如果本地宽带（尤其是部分移动宽带用户）对机场中转入口 IP 实施了临时路由阻断，手机开启 5G 热点让电脑连接测试；若热点下节点秒绿，证明为本地宽带 ISP 路由阻断，可在客户端中切换其他运营商入口的备用节点。

### 2. 故障 B：退出 Clash 后电脑彻底断网（连百度都打不开）
- **根因深度解密**：退出软件时由于直接关机、任务管理器强杀进程或程序异常崩溃，导致写入 Windows 注册表（`Internet Settings`）中的系统代理端口配置（`127.0.0.1:7897`）没有被正常擦除还原。此时本地所有浏览器仍固执地向已经关闭的本地端口发送请求，导致全网中断。
- **秒级自愈修复步骤**：
  - 打开 Windows “**设置**” -> 点击 “**网络和 Internet**” -> 找到 “**代理**”；
  - 查看“手动设置代理”选项，将 “**使用代理服务器**” 开关手动切换为 “**关**”，清空代理 IP 地址与端口，点击保存即可瞬间恢复网络！

### 3. 故障 C：端口冲突报错（Port 7890 / 7897 is already in use）
电脑后台同时运行了其他代理软件（如 v2rayN、旧版 CFW、加速器伴侣）霸占了核心端口。
- **解决方案**：打开 Verge Rev 设置，在“外部控制与端口设置”中，将“混合端口（Mixed Port）”由默认的 `7897` 改为一个冷门空闲端口（如 `17897` 或 `27897`），点击保存即可秒级避开冲突。

### 4. 故障 D：Windows 11 微软商店（Microsoft Store）与 UWP 应用无法联网
- **根因深度解密**：微软在 Windows 10/11 的 UWP 应用中引入了严格的“AppContainer 网络隔离”机制，默认禁止任何 UWP 沙盒应用向本机本地回环地址（`127.0.0.1`）发送网络请求。
- **解决方案**：在 Clash Verge Rev 左侧工具箱中，点击打开 “**Windows UWP 回环工具（Loopback Exemption）**”，在弹出的窗口中点击右上角“Exempt All（全选豁免）”，然后点击“Save Changes（保存变更）”，微软应用商店与 Xbox 即刻满血复活！

### 5. 故障 E：国内在线竞技游戏开启代理后延迟激增或防作弊报错
- **根因分析**：部分国内网游（如英雄联盟国服、无畏契约国服、永劫无间）的防作弊系统（ACE / TP）在检测到网络底层挂载了虚拟网卡驱动或网络请求被劫持时，可能会判定为第三方辅助插件而闪退报错，或由于小众游戏服务器 IP 未被 Geosite 命中而误走了海外节点。
- **解决对策**：在 Verge Rev 的“订阅扩展（Merge）”中添加规则：
  `- PROCESS-NAME,LeagueClient.exe,DIRECT` 与 `- PROCESS-NAME,Crossfire.exe,DIRECT`，强制指定游戏客户端主程序绕过内核，直接走本地网卡直连。

### 6. 故障 F：开启局域网共享（Allow LAN）后，手机连不上电脑的代理端口
- **根因分析**：Windows 高级防火墙在默认状态下，严格阻止来自同一局域网内其他设备对本机特定端口的入站连接。
- **解决对策**：进入 Windows Defender 防火墙设置，点击“高级设置” -> “入站规则” -> 新建规则 -> 选择“端口” -> TCP 端口填入 `7897` -> 操作选择“允许连接” -> 作用域覆盖“专用与公用网络”，保存后手机即可顺畅共享电脑上的高速专线节点。

## 十二、深度实战 FAQ 问答库

### Q1：Clash for Windows (CFW) 还能继续使用吗？有安全漏洞风险吗？
**坚决不建议继续使用！**
CFW 官方已于 2023 年底停止维护并永久删库。由于其基于老旧的 Electron 与 Chromium 内核打包，社区已披露其存在数个未修复的远程代码执行（RCE）高危安全隐患。此外，原版 CFW 无法支持 VLESS Reality 与 Hysteria 2 现代协议，遇到采用新协议的优质专线节点将直接无法解析。请尽快迁移至 **[Clash Verge Rev](/clash/verge/)**。

### Q2：Clash Verge 和 Clash Verge Rev 有什么区别？为什么要加一个“Rev”？
原版 `Clash Verge` 项目由原始作者启动，但在 2023 年底随着原版停更潮同样停止了开发。
随后，开源社区的核心开发者建立了分支（Fork），在原项目基础上成立了 **Clash Verge Rev**（Rev 代表 Revision / 社区维护重构版）。当前全网所有活跃更新、Bug 修复、新内核适配与功能迭代均出自 **Clash Verge Rev** 团队。请务必认准带有 `clash-verge-rev` 的官方项目地址。

### Q3：为什么开启了代理，但在 CMD / PowerShell 终端里 `git clone` 或 `pip install` 依然很慢？
因为 Windows 命令提示符（CMD）与 PowerShell **默认不继承操作系统的图形代理设置**！
- **方案一（推荐）**：在 Clash Verge Rev 中开启 **TUN 模式**，TUN 会在虚拟网卡层接管命令行所有网络，零配置即可让命令行秒速出海；
- **方案二（临时命令）**：在终端中手动输入并执行环境变量设置命令：
  `set http_proxy=http://127.0.0.1:7897 && set https_proxy=http://127.0.0.1:7897`（PowerShell 下使用 `$env:http_proxy="http://127.0.0.1:7897"`）。

### Q4：什么是 TUN 模式？开启 TUN 模式和普通系统代理有什么本质区别？
- **普通系统代理**：仅向操作系统注册了一个本地 HTTP/SOCKS 监听端口（如 `127.0.0.1:7897`）。只有主动读取该系统变量的软件（如 Chrome、Edge、Firefox 浏览器）才会自觉将流量发往该端口，其他大部分桌面游戏客户端、局域网工具、终端命令不会走代理。
- **TUN 模式**：通过虚拟网络适配器（Virtual TAP/TUN Adapter）在操作系统底层实现虚拟物理网卡接管。所有进出电脑网卡的 TCP/UDP 数据包在驱动层全部被截获并分流，能够完美加速外服游戏、Telegram 语音通话、CMD 命令行及 WSL 虚拟机。

### Q5：为什么开启 Clash 后，有些国内网站打不开或者提示异地登录异常？
这通常是因为你的分流规则没有正确配置，导致国内网站的域名请求被错误分流到了海外代理节点。
**自查排查**：
1. 检查客户端代理模式是否被误设为了“全局（Global）”，务必改回“规则（Rule）”；
2. 在 Verge Rev 设置中，点击“更新 GeoIP / Geosite 数据库”，确保本地维护的中国大陆 IP 与域名白名单保持最新；
3. 对于个别漏网的国内企业内部私有域名，可以在 Verge Rev 的“配置扩展”中手动添加一条 `DOMAIN-SUFFIX,你的域名.com,DIRECT` 强制直连规则。

### Q6：节点列表中的“自动选择 (URL-Test)”和“负载均衡 (Load-Balance)”有什么区别？日常该选哪个？
- **自动选择（URL-Test）**：客户端每隔固定时间（如 10 分钟）向指定测试服务器发送一次探测包，自动将所有后续连接流量导向当前**延迟最低的那单一节点**。适合日常绝大多数场景。
- **负载均衡（Load-Balance）**：将你的网络连接按哈希算法轮流分配给策略组内的多个节点并发传输。虽然理论上带宽大，但会导致你的公网 IP 频繁在不同国家之间跳跃漂移，极其容易触发 Google、OpenAI、银行账号的安全风控导致封号。**日常使用强烈建议选择“自动选择”或手动固定单一专线节点，切勿乱用负载均衡**。

### Q7：遇到订阅更新报“Invalid YAML format”或格式破损该怎么手动排查？
这通常是因为节点名称中包含了特殊 Emoji 图标，或者机场服务器返回的内容是 HTML 拦截网页而非结构化 YAML。
你可以直接用系统自带浏览器打开该订阅 URL：
- 如果页面显示的是 Cloudflare 拦截页面或报错网页，说明订阅被机场面板阻断；
- 如果页面下载了一份文件，用文本编辑器打开，检查第一行是否含有 `proxies:` 关键字声明；若没有，说明该链接是纯文本 Base64 格式，需在订阅末尾加上 `&flag=clash` 重新请求标准的 Clash 格式。

### Q8：为什么电脑从休眠状态唤醒后，Clash 经常出现全节点超时、网页无法打开？
因为电脑休眠时，操作系统的虚拟网卡驱动与后台网络套接字（Socket）被强行挂起中断。当系统唤醒后，Mihomo 核心与操作系统的网络过滤通道未能及时重建握手。
**秒级解决对策**：鼠标右键点击屏幕右下角任务栏的 Clash 图标，选择“重启内核（Restart Core）”或直接重启 Clash Verge Rev，网络即刻秒级恢复。

### Q9：在 macOS 苹果电脑上，开启 Clash Verge Rev 后为什么偶尔出现系统提示“辅助程序未安装”？
这是因为 macOS 系统拥有严格的系统扩展（System Extension）安全限制。开启 TUN 虚拟网卡需要向系统安装特权辅助工具（Privileged Helper Tool）。
**解决对策**：打开 macOS“系统设置” -> “隐私与安全性” -> 在底部找到“已阻止加载来自开发者 clash-verge-rev 的系统软件”，点击“允许”并输入开机解锁密码；随后在 Verge Rev 设置中重新点击安装 Service Mode，即可彻底打通内核通信链路。

### Q10：Clash Verge Rev 的便携免安装版（Portable）与安装版（Setup）有什么本质区别？
- **安装版（Setup.exe）**：自动将主程序写入 `Program Files` 目录，将用户个人配置存放在系统用户目录 `AppData\Roaming\clash-verge` 中，自带开机自启系统服务注册表挂载，适合个人固定电脑长期主力使用。
- **便携版（Portable.zip）**：解压即可运行，其所有日志、订阅配置、内核核心均严格存放在当前解压文件夹内，完全不向 Windows 系统注册表与 AppData 写入任何数据。你可以将整个便携版文件夹拷贝至 U 盘中，插到任何一台 Windows 电脑上直接即插即用，非常适合公司办公或公用电脑上的无痕使用。
